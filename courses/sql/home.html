Aprender SQL a ver as tabelas a mudar

Onze lições curtas, do primeiro SELECT aos JOIN e à normalização. Em cada exemplo carregas em "Seguinte" e vês que linhas passam o WHERE, como o GROUP BY faz os grupos e como o JOIN junta as tabelas.

Como usar

  1. Lê a explicação

    É curta de propósito. Se já fizeste o C do Zero, vais reconhecer muitas ideias.

  2. Corre o exemplo

    Antes de cada "Seguinte", tenta adivinhar que linhas vão passar e que resultado vai sair.

  3. Responde às perguntas

    Quase todas são "que resultado dá esta consulta?". Cada resposta traz a explicação.

  4. Faz os exercícios

    Escreve a consulta num SQLite antes de veres a solução, e compara com o resultado esperado.

Para o teste: a ordem em que o SQL trabalha

Escreve-se por uma ordem, mas o SGBD executa por outra. Saber isto resolve metade das dúvidas.

Uma consulta escreve-se começando pelo SELECT, mas o SGBD começa pelo FROM: primeiro tem de saber de que tabela vêm as linhas. Depois filtra, agrupa, e só no fim escolhe as colunas e ordena.

É por isso que o WHERE não pode usar COUNT(*) (os grupos ainda não existem) e que o ORDER BY já pode usar os nomes dados com AS (o SELECT já correu).

Nas perguntas "que resultado dá?", faz no papel o que o visualizador faz: escreve a tabela, risca as linhas que o WHERE tira, junta os grupos, e só no fim escolhe as colunas.

OrdemParteO que faz
1FROM / JOINvai buscar as tabelas e junta-as
2WHEREtira as linhas que não interessam
3GROUP BYjunta as linhas em grupos
4HAVINGtira os grupos que não interessam
5SELECTescolhe e calcula as colunas
6DISTINCTtira as linhas repetidas
7ORDER BYordena
8LIMITfica só com as primeiras

Onde praticar

  • No browser, sem instalar nada: SQLite Online ou DB Fiddle (escolhe SQLite). Abre "Ver o SQL que cria estas tabelas" na lição, copia, e depois escreve as tuas consultas.
  • No computador: o DB Browser for SQLite mostra as tabelas em grelha, como aqui.
  • Este curso usa o SQLite. Na cadeira podem usar MySQL, PostgreSQL ou Oracle: o SQL das lições é praticamente igual, mudam alguns tipos e pormenores (a cábula indica os principais).

Para quem está a explicar

  • Pede-lhe que diga que linhas vão passar antes de carregar em "Seguinte".
  • Desenhem as tabelas no papel. Nos JOIN, liguem com setas cada linha ao seu par.
  • Quando uma consulta dá um resultado estranho, tirem partes (o ORDER BY, o GROUP BY) e vejam o resultado a cada passo.
  • Leiam juntos as mensagens de erro: dizem quase sempre qual é a coluna ou a tabela com problema.
