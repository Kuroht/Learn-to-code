Aprender C# a ver a pilha e o heap

Onze lições curtas, do primeiro Console.WriteLine às classes, herança e interfaces. Em cada exemplo carregas em "Seguinte" e vês o que fica na pilha, que objetos estão no heap e que variáveis apontam para eles.

Como usar

  1. Lê a explicação

    É curta e compara com o C sempre que ajuda. As primeiras lições vão depressa, porque muita coisa é igual.

  2. Corre o exemplo

    Antes de cada "Seguinte", pergunta-te: isto copia o valor, ou copia uma referência para o mesmo objeto?

  3. Responde às perguntas

    "O que aparece no ecrã?" e também "isto compila?". Cada resposta traz a explicação.

  4. Faz os exercícios no computador

    Escreve e corre o programa antes de abrires a solução. A dica ajuda a começar.

Para o teste: valor ou referência?

A pergunta que resolve quase todos os exercícios de "o que aparece no ecrã?" com objetos.

Antes de seguires o código, vê o tipo de cada variável. Se é um tipo de valor (int, double, bool, struct), b = a faz uma cópia independente.

Se é um tipo de referência (uma class, um array, uma List), b = a faz as duas variáveis apontarem para o mesmo objeto. Mudar um campo através de uma vê-se pela outra.

No papel, desenha a pilha à esquerda e o heap à direita, com uma seta de cada referência para o seu objeto. Cada new é uma caixa nova no heap.

b.X = 9a.X = 1, b.X = 9a.X = 9, b.X = 9

Onde praticar

  • No browser, sem instalar nada: .NET Fiddle. Escolhe o compilador mais recente e cola o código.
  • No teu computador: instala o .NET SDK, cria um projeto com dotnet new console e corre-o com dotnet run. O código vai no ficheiro Program.cs.
  • Com o Windows em português, os reais aparecem com vírgula (3,5). Nos exemplos do curso aparecem com ponto.

Para quem está a explicar

  • Pede-lhe que diga, em cada atribuição, se é uma cópia ou uma referência, antes de carregar em "Seguinte".
  • Leiam juntos os erros de compilação: o código (CS0029, CS0165...) e a mensagem dizem quase sempre o que falta.
  • Nas lições 9 e 10, desenhem as classes como caixas ligadas por setas "é um".
  • Se o C estiver fresco, comparem: o ref é o apontador do C, e um objeto é um struct que vive no heap.
