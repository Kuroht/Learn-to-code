Aprender TypeScript a ver os erros antes de correr

Onze lições curtas, dos tipos básicos às interfaces, uniões, classes, genéricos e async/await. Em cada exemplo carregas em "Seguinte": ou o programa corre e vês as variáveis e os objetos, ou o compilador para-o antes, com o erro marcado na linha.

Como usar

  1. Lê a explicação

    É curta e assume que já fizeste o JavaScript do Zero: aqui só se acrescentam os tipos.

  2. Corre o exemplo

    Antes de cada "Seguinte", pergunta-te: isto compila? Se não compilar, nada corre, nem as linhas certas.

  3. Responde às perguntas

    "O que aparece no ecrã?" e "isto compila?". As respostas com erros são as mensagens reais do compilador.

  4. Faz os exercícios no computador

    Escreve o ficheiro .ts, compila com tsc e corre o .js com o Node.

O que o TypeScript apanha (e o JavaScript não)

Os mesmos enganos do curso de JavaScript, agora parados antes de o programa correr.

Em JavaScript, a maior parte dos enganos não dá erro: dá um valor estranho (NaN, undefined, "53") que só descobres mais tarde, longe do sítio onde está o problema.

O TypeScript lê o programa todo antes de ele correr e diz-te a linha e o motivo. Para os erros, lê o código (TS2322, TS2345...) e a frase: quase sempre dizem o tipo que esperava e o que recebeu.

Os tipos não existem a correr. Um valor que vem de fora (um formulário, um servidor) continua a precisar de ser verificado e convertido.

Onde praticar

  • No browser, sem instalar nada: o TypeScript Playground, o site oficial. Mostra os erros enquanto escreves e o JavaScript que sai.
  • No teu computador: com o Node instalado, npm install -g typescript. Compila com tsc --strict programa.ts e corre com node programa.js.
  • No VS Code, os erros aparecem sublinhados a vermelho enquanto escreves, antes até de compilares.

Para quem está a explicar

  • Em cada exemplo, pede-lhe que diga se compila antes de carregar em "Seguinte".
  • Quando aparece um erro, leiam a mensagem juntos: "Type X is not assignable to type Y" diz exatamente o que não bate certo.
  • Resistam ao any: quase sempre há um tipo certo, e encontrá-lo ensina mais do que calar o compilador.
  • Lembrem-se de que as regras do JavaScript continuam todas lá: referências, ===, a ordem do async.
